## Реалізований обсяг

P1–P5 реалізовані: два подання живого монітора, авторизоване незалежне вікно, обмежений ТВ-токен, деталі й переходи до потрібного принтера/черги, сортування, групування, Авто/S/M/L/XL, обидві мови й теми. Керувальних команд на екрані немає.

Вибір оболонки відбувається в `main.tsx` до імпорту основного `App`: ТВ не монтує Auth/WS/stream providers і не запускає їхні запити. Знімок монітора зберігається в окремому локальному hook, із AbortController, backoff і спільним завершенням обох feeds після втрати доступу. Секрет не входить до query keys або local storage.

Backend використовує `peek_status`, справжній head черги до ownership-фільтра й обмежений DTO. Міграція m170 додає типовану причину очікування; ORM-зміни та bulk lifecycle operations очищують її разом із поясненням. Нагрівання/передавання/зміна столу мають явний dispatch phase. Збій спостерігача етапу не перериває запуск після ввімкнення нагрівачів.

## Середовище

Windows, Python 3.12.10, Node 24.17.0, Edge/Chromium через Playwright. Перевірено Vite production bundle з реальним FastAPI та окремою SQLite-базою: 50 тестових принтерів, 150 pending rows, контрольована телеметрія. Background workers обладнання вимкнені. Окремі перевірки класифікації/щільності використовують контрольовані відповіді API; вони не підміняють перевірку серверної авторизації.

## Виміри API

По 12 послідовних запитів на локальному стенді, під час інших перевірок. Це виміри цього Windows-хоста, а не обіцянка затримки на іншому обладнанні. ТВ-виміри включають перевірку hash токена.

| Feed, 50 принтерів | JSON, байт | Медіана | p95 |
|---|---:|---:|---:|
| ТВ snapshot, Черга | 34 242 | 118 мс | 233 мс |
| ТВ forecast | 4 783 | 100 мс | 131 мс |
| Авторизований snapshot | 38 127 | 101 мс | 175 мс |

Production-клієнт, 50 плиток: у п’яти повторних навігаціях час від відкриття URL до готової 50-ї плитки — 645–968 мс, медіана 958 мс. Після одноразової ініціалізації shared modal portal десять циклів «Черга → деталі → Принтери» залишили 484 JS listeners; кількість DOM nodes — 2152 → 2148. Ще через 30 с роботи — ті самі 484 listeners / 2148 nodes, 239 мс script time і 1 мс layout time за цей інтервал. Це короткий профіль конкретного браузера, не доказ відсутності будь-яких витоків пам’яті. Помилок сторінки немає.
